## Secondary attacks (right click)
- CharacterData has an optional secondary_attack_scene (same rules as attack_scene: the root script must extend
  Attack; empty = no secondary). Player.set_character() instantiates it into player.secondary_attack, and the player
  configures, ticks, starts and cancels it exactly like the primary. It gets the same configure() numbers and
  decides which of them it uses. The "attack_secondary" input action (right mouse) is registered in code in
  player.gd _register_inputs() if it doesn't already exist in the Input Map.
- Input: player.gd _handle_attack_input() polls the held right button FIRST and on its own, then the primary. So
  right click fires whether or not left click is held or the primary is mid-swing. Both are skipped while an
  attack is moving the player (a dash).
- Attack interface gained two optional hooks (defaults keep old attacks working):
  - is_busy() -> bool: true while the attack is mid-swing / mid-cast. SlashAttack: while slashing.
    DashAttack: during wind-up and dash.
  - can_start_while(primary: Attack) -> bool: asked by the player before it triggers a SECONDARY. Default true.
- Nico (cat): ThrowingKnifeAttack (throwing_knife_attack.gd) + knife_projectile.gd (class KnifeProjectile, group
  "knives", cancel() clears it) + cat_knife_attack.tscn. Small, fast, low-damage knife toward the mouse; hits the
  first mob it touches. Defaults: cooldown 1.05s (about a third of the original 0.35s rate), speed 1400, range 750,
  damage_fraction 0.5 of the character's damage (min 1). It overrides can_start_while so it CANNOT be thrown while
  Nico's slash is mid-swing (a refused throw doesn't use up the cooldown).
- Seven (android): a DashAttack as the secondary. windup_time is 0 on its scene, so the dash starts the instant
  the button is pressed (no wind-up line, no slowdown). It uses DashAttack's optional extras: slam_delay (the
  shockwave lands a moment AFTER the dash ends, at the spot where the dash ended, shown as a danger zone) and
  knockback_enabled = false (damage only). Unlike the knife, it can be used during a slash. While the shockwave charges, DashAttack.is_controlling_movement() stays true (export lock_until_slam), so Seven is rooted until it lands; it follows the _slam_pending state, not a timer.
- Values saved in the attack .tscn files override script defaults: if a nerf or tweak doesn't seem to apply
  (knife attack_cooldown, Seven's windup_time), check the scene's root node in the Inspector.
- Seven's and Nico's secondaries use the same shop upgrades as their primaries (damage, attack_range, attack_speed,
  plus dash_distance / knockback where the scene reads them). No separate upgrade line exists yet.

## Architecture in a few lines
- Main (Node) owns Player, HUD and the timers. HUD emits start_game(character) when PLAY is pressed;
  Main.new_game(character) calls Player.set_character(character), then Player.start().
- Characters are DATA: a CharacterData resource (.tres) per character. CharacterRoster lists them.
- Attacks are SCRIPTS that extend Attack. A character points at an attack SCENE (a tiny .tscn whose
  root node uses the attack script). Player.set_character() instantiates it and adds it as a child.
  A character can also point at a secondary_attack_scene, fired with right click.
- SaveData is static (no autoload). Coins are shared; upgrade levels are stored per character id.

## Files
Characters and roster
- character_data.gd (class CharacterData, Resource): id, display_name, description, sprite_frames,
  sprite_tint, speed, base_max_health, base_attack_damage, regen_interval (0 = none), attack_scene,
  secondary_attack_scene (optional, right click), upgrade_ids (what the shop offers; empty = everything), upgrade_overrides ({id: {name, desc}}).
- character_roster.gd (class CharacterRoster): PATHS list in selection-screen order; all(), find_by_id().
- cat.tres, bruiser.tres, android.tres, dragon.tres; cat_frames.tres is the shared sprite frames.
  Non-cat characters are the cat sprite with a sprite_tint (grey, red, yellow) until real art exists.
  Sprite frames must contain the animations "walk" and "up" (player.gd plays them).

Attacks
- attack.gd (class Attack, extends Node2D): the interface. The player only calls these:
  - configure(damage, range_mult, speed_mult, bonuses) at the start of each run. `bonuses` is a
    dictionary of EVERY upgrade's bonus by id; read your own unique ones with bonus("id").
  - start_run(), cancel(), tick(delta), try_attack(target) -> bool.
  - is_controlling_movement(): true while the attack moves the player itself (dash); the player then
    skips its normal movement and attack input.
  - is_invulnerable(): true while the player should take no damage; checked in Player.take_damage().
  - is_busy() and can_start_while(primary): see "Secondary attacks" above. The player also checks the
    secondary's is_controlling_movement(), movement_speed_multiplier() and is_invulnerable().
- slash_attack.gd (class SlashAttack) + cat_slash_attack.tscn + android_slash_attack.tscn.
  The slash and all the slash-art exports live on the attack scene's root node. Per-attack values saved
  in those .tscn files (slash_time, slash_frames, slash_flip_y, slash_angle_offset...) override script defaults.
- projectile_attack.gd (class ProjectileAttack) + projectile.gd (class Projectile) + dragon_projectile_attack.tscn.
  Projectiles are added to the CURRENT SCENE (not under the player), join group "projectiles", and
  cancel() clears that group. They are drawn in code.
- dash_attack.gd (class DashAttack) + bruiser_dash_attack.tscn. Moves the player in tick(), then _slam():
  damage + mob.knockback(). Drawn in code. Optional extras for secondary use: slam_delay (delayed shockwave
  at the dash's end point), knockback_enabled (false = damage only). windup_time 0 = instant dash.
- throwing_knife_attack.gd (class ThrowingKnifeAttack) + knife_projectile.gd (class KnifeProjectile) +
  cat_knife_attack.tscn: Nico's secondary. Knives are added to the CURRENT SCENE, join group "knives".

Core
- player.gd: set_character(data) copies stats, swaps sprites/tint, instantiates the attack, and calls
  SaveData.set_character(id, upgrade_ids, upgrade_overrides). apply_upgrades() builds the bonuses
  dictionary and calls attack.configure(). Regeneration lives here (_update_regen). The @export
  `character` on the Player node in player.tscn is only a default (cat.tres); at runtime Main overrides it.
- mob.gd: take_damage(), knockback(direction, speed, duration) (tweens linear_velocity back to the mob's
  normal velocity), died signal, hit_radius used by ALL attacks' hit tests.
- main.gd: constants for score/coins/mob health; new_game(character = null) sets the character first.
- hud.gd: health bar, coins, results, shop, reset button + dialog, and the selection screen
  (_build_select_screen, _refresh_select, _make_card, _on_play_pressed). The shop shows the SELECTED
  character's upgrades (hud calls SaveData.set_character before opening it).
- save_data.gd (class SaveData): UPGRADES dictionary (9 upgrades, see DESIGN_NOTES); per-character levels;
  get_level / bonus / get_cost / try_buy use the CURRENT character (set with set_character);
  get_level_for / bonus_for work for any character (used by the selection cards);
  available_upgrades(), upgrade_info(id) (applies the per-character wording overrides);
  get/set_last_character(). Save file sections: [progress] coins + last_character, [upgrades_<id>] per character.

## Conventions and gotchas learned (please follow these)
- Indentation is TABS. Mixed tabs/spaces breaks GDScript. After writing a .gd file, check with
  grep -cP '^\t' and grep -cP '^ +\S'. (The shell is plain sh: no process substitution.)
- GDScript type inference: an untyped export (@export var x = 1.0) makes `var y := x * 2` fail
  with "Cannot infer the type". Declare exports with := or an explicit type.
- You cannot run Godot in your sandbox, so code is untested until the user runs it. Say so, and ask the
  user to paste any error message they get. Common cause of "unknown class" errors or a missing Character
  field: new scripts not registered yet, or a file from an earlier step not copied. Try Project > Reload
  Current Project, and check every file from earlier steps is in the project.
- Versions drift. The user edits files in other chats and uploads files with suffixes
  (player_1.gd, main_1.tscn, ...). Always read the latest uploads, diff against what you last
  produced, and base edits on THEIR version. Before blaming a setting, check their file actually
  contains your change (this caused a real mix-up once, and once a missing file from an earlier step caused a "no player" report).
- Values saved in a .tscn/.tres (set in the Inspector) override script defaults.
- Prefer building new UI/nodes in code over editing .tscn files by hand. If a .tscn must change,
  keep the edit small and explain it. (Character and attack scenes were written by hand: keep their format.)
- The Attack.configure signature has FOUR arguments now. Any new attack type must match it, and call
  super.configure(...) first.
- Mobs are hit with distance + each mob's hit_radius (not their collision shape). New attacks should reuse that.
- Deliver complete updated files, or all the files that changed, and say which are new and which replace old ones.
- Keep replies plain and concrete. The user likes short step-by-step explanations, a "To test" list
  after each step, and a question about the next step at the end.
